# DENTARA + Outreach Agent

Два самостоятельных проекта в одном репозитории: **DENTARA**, демонстрационный сайт стоматологической клиники, и **Outreach Agent**, локальный инструмент исследования B2B-компаний, подготовки писем и ручного контроля отправки.

| Компонент | Технологии | Запуск |
| --- | --- | --- |
| DENTARA | HTML, CSS, JavaScript, WebP; без сборки | `python -m http.server 8080 --bind 127.0.0.1` из корня |
| Outreach API + dashboard | Python 3.14, SQLite, стандартная библиотека | `python -m app.server` из `outreach-agent` |
| Research service | Отдельный HTTP-процесс, без БД и SMTP | `python -m app.research.server` из `outreach-agent` |
| Локальный анализ | LM Studio + `qwen/qwen3-vl-8b` | OpenAI-совместимый сервер на порту 1234 |

[Архитектура и HTTP-контракты](docs/architecture.md) · [Результаты проверки](docs/audit.md) · [Рабочие сценарии Outreach Agent](outreach-agent/README.md)

## Быстрый старт

```powershell
git clone https://github.com/Yernaribadulla/outreach-agent.git
cd outreach-agent
python -m http.server 8080 --bind 127.0.0.1
```

Откройте [DENTARA](http://127.0.0.1:8080). Для статического сайта не нужны npm, установка пакетов или фреймворк. Можно открыть `index.html` напрямую; HTTP-режим удобнее для разработки и проверки ресурсов.

Для рабочего приложения откройте второй терминал в корне репозитория:

```powershell
cd outreach-agent
python -m venv .venv
.\.venv\Scripts\Activate.ps1
Copy-Item .env.example .env
python -m app.server
```

Откройте [Outreach dashboard](http://127.0.0.1:8765). Python-приложение использует стандартную библиотеку: `pip install` не требуется. Команды Python также работают на Linux/macOS; активация окружения там — `source .venv/bin/activate`.

## DENTARA

Сайт представляет концепцию вымышленной клиники в Алматы. Структура ведёт от знакомства с подходом к услугам, пространству, первому визиту, вопросам и демонстрации записи.

- Спокойная зелёно-кремовая палитра, редакционная типографика, две темы.
- Адаптивная композиция для телефона, планшета и десктопа.
- Выбор направления с описанием, демонстрационной стоимостью и переходом в запись.
- Галерея с подписями и альтернативным текстом.
- FAQ на нативных `details` / `summary`, работающий без JavaScript.
- Запись: выбор услуги → контактные данные → проверка → завершение демо.
- Проверка имени и телефона, сохранение введённого при возврате на предыдущий шаг.
- Нативные модальные окна: фокус внутри, Escape, возврат к открывшей кнопке.
- Skip-link, видимый фокус, поддержка `prefers-reduced-motion`.
- Локальные WebP-изображения, отложенная загрузка второстепенных фото, отсутствие внешних шрифтов и карты.

**Запись демонстрационная.** Форма не вызывает API, не отправляет данные, не сохраняет контакты в localStorage и не назначает приём. При закрытии данные удаляются из формы и её состояния. В localStorage хранится только тема; при запрете хранилища переключение продолжает работать в памяти.

Цены, описания и изображения иллюстративны. На странице нет вымышленных отзывов, врачебных биографий, рейтингов, свободных слотов или обещаний результата. До реального запуска потребуются подтверждённые данные клиники, права на материалы и отдельный backend записи.

Визуальные ориентиры: [Tend](https://www.hellotend.com/site/home) — простая запись и спокойная коммуникация; [Ten Dental](https://www.tendental.com/) — понятная организация направлений. Тексты и бренд DENTARA самостоятельные; материалы этих сайтов не переносились.

### Где редактировать сайт

| Файл | Ответственность |
| --- | --- |
| `index.html` | Семантическая структура, основной текст, FAQ |
| `styles.css` | Токены темы, компоненты, адаптивные правила |
| `js/content.js` | Каталог услуг и галерея |
| `js/dialogs.js` | Общий жизненный цикл модальных окон и меню |
| `js/booking.js` | Состояние и проверка демонстрационной записи |
| `script.js` | Инициализация услуг, галереи, темы и навигации |
| `assets/` | Медиа, оптимизированные WebP и исходные материалы |

Классические `defer`-скрипты оставлены намеренно: сайт работает без сборки и с `file://`. Код разделён по ответственности через пространство имён `Dentara`.

## Outreach Agent

```text
Discovery → Entity resolution → Website research → Evidence
→ Local AI analysis → Qualification → Draft → Human review
→ Explicit simulated/SMTP send
```

Факты собираются детерминированно. Локальная модель должна опираться на переданные evidence, сохранять provenance и различать `CONFIRMED`, `INFERRED`, `UNKNOWN`, `NOT_DETECTED`. Ненайденная функция не объявляется отсутствующей. Некорректный модельный ответ не превращается в успешную квалификацию.

Приложение поддерживает discovery по вертикали и географии, SQLite-историю, анализ и черновики, Review Queue с сохранённым выбором, фоновые пакетные задания, остановку и явное продолжение после перезапуска. Ошибки отдельной компании не должны прерывать весь пакет.

### LM Studio

1. Загрузите `qwen/qwen3-vl-8b` в LM Studio.
2. Запустите локальный API на `http://127.0.0.1:1234/v1`.
3. При необходимости задайте `LM_STUDIO_BASE_URL` в локальном `.env`.

Автоматической замены модели нет. Просмотр dashboard и research-сервис не требуют работающей модели; анализ и генерация писем требуют.

### Отдельный research-сервис

Операции исследования сайтов вынесены за версионированную HTTP-границу. Сервис можно запускать и перезапускать независимо от dashboard. У него нет доступа к базе, отправке писем или LM Studio.

В терминале из вложенного `outreach-agent`:

```powershell
python -m app.research.server
```

В `.env` приложения:

```dotenv
RESEARCH_SERVICE_URL=http://127.0.0.1:8766
RESEARCH_SERVICE_TOKEN=
```

Перезапустите dashboard после изменения конфигурации. Если используете токен, задайте одинаковое значение обоим процессам. Пустой `RESEARCH_SERVICE_URL` сохраняет локальное выполнение функций в процессе приложения. При указанном URL и недоступном сервисе результат становится `UNKNOWN`: скрытого переключения на локальное выполнение нет.

Проверка готовности: [research health](http://127.0.0.1:8766/healthz).

Для контейнера из корня репозитория задайте `RESEARCH_SERVICE_TOKEN` в окружении и выполните:

```powershell
docker compose up --build research
```

Порт контейнера доступен только на `127.0.0.1:8766`. Токен обязателен при прослушивании не-loopback адреса. Сборка требует доступного Docker Engine. Python-запуск контейнеров не требует.

### Конфигурация

| Переменная | Значение по умолчанию / назначение |
| --- | --- |
| `OUTREACH_DB_PATH` | `outreach-agent/data/outreach.db`; задаётся в окружении процесса до запуска |
| `OUTREACH_PORT` | `8765`; задаётся в окружении процесса до запуска |
| `LM_STUDIO_BASE_URL` | `http://127.0.0.1:1234/v1` |
| `LM_STUDIO_MODEL` | Только `qwen/qwen3-vl-8b` |
| `RESEARCH_SERVICE_URL` | Пусто: локальный адаптер; URL: отдельный сервис |
| `RESEARCH_SERVICE_TOKEN` | Bearer-токен между приложением и research |
| `RESEARCH_HOST`, `RESEARCH_PORT` | `127.0.0.1`, `8766` |
| `SIMULATED_SEND` | `true`; симуляция без SMTP-доставки |
| `DENTARA_DEMO_URL` | Ссылка на демо для черновиков; настраивается владельцем |

Переменные процесса имеют приоритет над `.env`. `.env` — простой файл `KEY=value` без shell-интерполяции и снятия кавычек. Секреты не коммитятся.

### CLI

Из вложенного `outreach-agent`:

```powershell
python -m app.cli discover --vertical dental --city Астана --target 10 --provider osm
python -m app.cli autonomous --vertical dental --city Астана --target 5 --dry-run
python -m app.cli import-discovery --vertical dental --file gemini_batch_001.json
```

Импорт сохраняет происхождение данных и не делает их автоматически проверенными. Публичные источники могут быть недоступны или требовать CAPTCHA; обход защит не реализован.

### Отправка писем

По умолчанию `SIMULATED_SEND=true`. Реальный SMTP уже реализован в приложении и требует явного включения, настройки транспорта и подтверждения выбранного набора писем. Одобрение черновика само по себе ничего не отправляет.

Сохраняются проверки suppression, публичного источника email, готовности, дублей, лимитов и снимка выбранных получателей. Неопределённый результат прерванной SMTP-попытки не повторяется автоматически. Во время проверки репозитория реальные письма не отправлялись.

## Проверки

Из корня:

```powershell
node --check script.js
node --check js/content.js
node --check js/dialogs.js
node --check js/booking.js
node --check outreach-agent/app/ui/review.js
cd outreach-agent
python -m compileall -q app tests
python -m unittest discover -s tests -q
```

CI запускает Python-тесты на Windows и Ubuntu, а также синтаксическую проверку JavaScript. Тесты research-сервиса работают через локальный HTTP-fixture; внешние сайты, LM Studio и SMTP не нужны. Тесты Python используют временные базы.

Ручная браузерная проверка и ограничения описаны в [отчёте](docs/audit.md). Система остаётся локальным MVP: оркестрация discovery, анализа и отправки пока находится в API-процессе. Research — первый выделенный сервис; это не заявление о завершённом разделении всей системы на микросервисы.
