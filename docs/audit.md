| Архитектура | Исследование публичных сайтов выполнялось внутри приложения | Отдельный research-процесс с `/v1`, клиентом, healthcheck и контейнерным описанием |
| Документация | Root README отрицал существование вложенного README и реального SMTP | Разделены краткий старт, архитектура и инструкции оператора; исправлены режимы отправки |

## Измеримые изменения

- Четыре исходных JPEG: **4 079 871 байт**. Их используемые сайтом WebP-версии: **203 146 байт**, примерно **−95%**. Содержимое фотографий не заменялось; выполнены уменьшение разрешения и перекодирование.
- CSS: **46 809 → 21 878 байт**, примерно **−53%** при читаемом форматировании.
- JavaScript: исходный `script.js` — **19 948 байт**; новый script и три модуля вместе — около **15 KB**. При этом добавлены проверка и сохранение состояния формы.
- Регрессионная проверка подтверждает одинаковое число SELECT-запросов для списка из 1 и 25 компаний. Это проверка числа запросов, а не заявление об измеренном ускорении всей системы.

## Объём архитектурного изменения

Выделен настоящий независимо запускаемый research-сервис. API остаётся владельцем SQLite, review и отправки; LM Studio уже является отдельным процессом. Оставшаяся оркестрация не объявляется полностью переработанной микросервисной системой. Обоснование и следующий этап разделения описаны в [архитектуре](architecture.md).

## Границы результата

DENTARA остаётся демонстрацией: нет backend записи, реальных контактов, подтверждённых специалистов и проверенных лицензий исходных медиа. Перед коммерческим запуском их должен предоставить владелец клиники.

Живой discovery и качество конкретной локальной модели не проверялись на реальных компаниях. SMTP проверялся существующими mock/simulated тестами; реальные письма не отправлялись. Dashboard предназначен для локальной работы. Изменения не добавляют публичную аутентификацию, распределённую очередь или гарантию сетевой изоляции research.

CI настроен на Windows/Ubuntu и проверку JavaScript; результаты GitHub Actions следует оценивать по фактическому запуску workflow в pull request.
